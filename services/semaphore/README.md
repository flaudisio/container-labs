# Semaphore

Configuration for deploying a complete [Semaphore](https://semaphoreui.com/) stack. Currently used
in my homelab.

## Components

Six services on the default compose network. `semaphore` is the only one with a stable
in-network alias, `semaphore.local:3000`, which the runner, exporter and MCP server call.

| Service | Image | Role |
| --------- | ----- | ---- |
| `postgres-server` | `postgres:18-alpine` | Semaphore database (PostgreSQL 18) |
| `semaphore` | `flaudisio/semaphore-server:2.20.23` | Web UI, API and scheduler |
| `runner-01` | `flaudisio/semaphore-runner:2.20.23-ansible-2.21` | Task runner with Ansible 2.21 |
| `postgres-backups` | `prodrigestivill/postgres-backup-local:18-alpine` | Scheduled DB dumps |
| `exporter` | `vremenar/semaphore-prometheus-exporter:1.4.0` | Prometheus metrics |
| `mcp` | `ghcr.io/cloin/semaphore-mcp:1.0.6` | MCP server over HTTP |

Every image is pinned by digest; bump the tag and digest together.

### Host paths

| Service | Host path | Container path |
| --------- | --------- | -------------- |
| `postgres-server` | `/srv/container-labs/semaphore/postgres-server` | `/var/lib/postgresql` |
| `semaphore` | `/srv/container-labs/semaphore/server-config` | `/etc/semaphore` |
| `semaphore` | `/srv/container-labs/semaphore/server-tmp` | `/tmp/semaphore` |
| `runner-01` | `/srv/container-labs/semaphore/runner-01-config` | `/etc/semaphore` |
| `runner-01` | `/srv/container-labs/semaphore/runner-01-tmp` | `/tmp/semaphore` |
| `postgres-backups` | `/srv/container-labs/semaphore/postgres-backups` | `/backups` |
| `exporter` | `/srv/container-labs/semaphore/exporter` | `/data` |

`exporter` runs as `593:593` and `mcp` as `601:601`, so their host dirs must be owned by those
ids. `postgres-backups` runs as `postgres:postgres`; see [PostgreSQL backups](#postgresql-backups)
for the required ownership.

### Database and backups

- `postgres-server` reads `POSTGRES_DB`, `POSTGRES_USER` and `POSTGRES_PASSWORD`; Semaphore and
  the backup container reuse the same values.
- `postgres-backups` dumps every 2 hours at minute 5 into `/backups`, keeping 30 days, 12 weeks
  and 6 months, with compression level 3 and large objects included.
- Restores are manual — see [PostgreSQL backups](#postgresql-backups).

### Semaphore server

- Listens on `17300` on the host, `3000` in the container. `SEMAPHORE_WEB_ROOT` must be the URL
  users reach it on.
- The admin user is created on first boot from `SEMAPHORE_ADMIN*`; changing those later does not
  reset an existing account.
- Access keys, cookies and sessions are encrypted with `SEMAPHORE_ACCESS_KEY_ENCRYPTION`,
  `SEMAPHORE_COOKIE_HASH` and `SEMAPHORE_COOKIE_ENCRYPTION`; rotating any of them logs everyone
  out and invalidates stored credentials.
- Audit log is on (`main` instance, 7-day retention); Telegram alerts fire when
  `SEMAPHORE_TELEGRAM_CHAT` and `SEMAPHORE_TELEGRAM_TOKEN` are set.

### Runner

- Registers against `http://semaphore.local:3000` with `SEMAPHORE_RUNNER_TOKEN`, so it is
  pinned to this stack instead of reaching the server over the host network.
- Ansible versioning lives in the runner image, which keeps `ansible-*` tooling independent of
  the server image.
- Forwards `ANSIBLE_GALAXY_SERVER_*` to jobs; the Galaxy proxy is external to this stack
  (`galaxy-proxy.home.flaudisio.cloud`), not a compose service.

### Exporter and MCP server

- `exporter` scrapes the API every minute on `17900` (host) / `9090` (container) with
  `SEMAPHORE_EXPORTER_API_TOKEN`; it caches the last response in `/data/cache.json` and keeps
  the last 100 events.
- `mcp` serves MCP over HTTP on `9500` (host) / `9000` (container) with
  `SEMAPHORE_MCP_API_TOKEN`.
- Both tokens are created in the Semaphore UI, not generated by this stack.

## PostgreSQL backups

Required setup **before** running the backup container for the first time:

```bash
# Default images (Debian-based)
sudo mkdir -pv /srv/container-labs/semaphore/postgres-backups
sudo chown -Rv 999:999 /srv/container-labs/semaphore/postgres-backups

# Alpine images
sudo mkdir -pv /srv/container-labs/semaphore/postgres-backups
sudo chown -Rv 70:70 /srv/container-labs/semaphore/postgres-backups
```

Create backup manually:

```bash
docker compose exec postgres-backups /backup.sh
```

View existing backups:

```bash
docker compose exec postgres-backups sh -c 'find /backups -type f | sort'
```

Restore backup:

```bash
docker compose cp postgres-backups:/backups/last/semaphore-XXXXXXXX-XXXXXX.sql.gz /tmp/backup.sql.gz
docker compose cp /tmp/backup.sql.gz postgres-server:/tmp/backup.sql.gz

docker compose exec postgres-server sh
zcat /tmp/backup.sql.gz | psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"
```
